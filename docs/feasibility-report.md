# 実現可能性レポート: Pico 2W + PIO で LTA042B010F を駆動

## エグゼクティブサマリー

**結論: 実現可能。技術的な障壁は低い。**

Raspberry Pi Pico 2W (RP2350) の PIO で LTA042B010F (400×96 RGB666 TFT LCD) を駆動することは十分に実現可能である。コミュニティによるリバースエンジニアリングでピンアサイン・タイミング仕様は完全に解明されており、ESP32-S3・STM32・AVR・FPGA等の多数の成功事例がある。

## 評価マトリクス

| 評価項目 | 判定 | 詳細 |
|---------|------|------|
| GPIO ピン数 | ✅ 可能 | RGB666: 20本 (TEST/Pin6をGND固定時), RGB444: 15本 |
| ピクセルクロック | ✅ 余裕 | 3-4MHz必要。PIOは最大75MHz出力可能 |
| メモリ (SRAM) | ✅ 余裕 | フレームバッファ75KB。520KB中で十分 |
| DMA 帯域 | ✅ 余裕 | 3-4MB/s程度。最大600MB/sの1%以下 |
| PIO リソース | ✅ 余裕 | 2-3 SMで実装可能。12SM中余裕あり |
| データシート | ✅ 解明済 | コミュニティ解析でピンアサイン・タイミング確定 |
| 電源回路 | ⚠️ 要設計 | ±12V生成 + CCFLインバーター必要 |
| 電圧レベル | ✅ 互換 | 3.3Vロジックで動作確認済み |
| 先行事例 | ✅ 多数 | ESP32-S3, STM32, AVR, FPGA等で成功 |

## 詳細分析

### 1. GPIO ピン数

#### RGB666 接続（20 GPIO）
```
B[5:0] = 6ピン  (Pin 8-13)
G[5:0] = 6ピン  (Pin 15-20)
R[5:0] = 6ピン  (Pin 22-27)
NCLK   = 1ピン  (Pin 2)
HSYNC  = 1ピン  (Pin 4)
VSYNC  = 1ピン  (Pin 5)
TEST   = GND固定 (Pin 1)
Pin 6  = GND固定
──────────────
合計    = 20 GPIO
```

#### RGB444 簡易接続（15 GPIO）
```
B[3:0] = 4ピン  (Pin 10-13, 上位2bitはGND)
G[3:0] = 4ピン  (Pin 17-20, 上位2bitはGND)
R[3:0] = 4ピン  (Pin 24-27, 上位2bitはGND)
NCLK   = 1ピン
HSYNC  = 1ピン
VSYNC  = 1ピン
──────────────
合計    = 15 GPIO
```

**Pico 2W の利用可能 GPIO**:
- 総GPIO: 30本
- 無線 (CYW43439): GPIO 23, 24, 25, 29 使用
- 実質利用可能: 約26本
- LCD接続後の残り: **6〜11本**（I2C, SPI, UART等に使用可能）

### 2. メモリ

```
RP2350 SRAM: 520 KB

フレームバッファサイズ:
  RGB565 (16bpp): 400 × 96 × 2 = 76,800 bytes (75 KB)
  RGB444 (12bpp): 400 × 96 × 1.5 = 57,600 bytes (56.25 KB)
  
ダブルバッファリング:
  RGB565 × 2: 150 KB
  RGB444 × 2: 112.5 KB

残りSRAM（ダブルバッファ後）:
  RGB565: 520 - 150 = 370 KB → アプリケーション用に十分
```

### 3. ピクセルクロック

```
目標: 60Hz表示
  H_total = 512 clk, V_total = 112 lines
  DCLK = 512 × 112 × 60 = 3.44 MHz

PIO分周:
  システムクロック 150MHz / 3.44MHz = 43.6
  → 分周比 44 で DCLK ≈ 3.41 MHz (60Hz近似)
  → 分周比 43 で DCLK ≈ 3.49 MHz (OK)
```

### 4. PIO ステートマシン構成案

```
PIO Block 0:
  SM0: タイミングコントローラ
       - HSYNC パルス生成
       - VSYNC パルス生成（HSYNC開始+98clk後にサンプリングされる点に注意）
       - ブランキング期間のカウント
  SM1: ピクセルデータ出力
       - DMA から受け取った RGB データを GPIO に出力
       - NCLK 同時生成（サイドセット機能）

DMA:
  CH0: フレームバッファ → SM1 FIFO（スキャンライン自動転送）
  CH1: チェーンDMA でスキャンラインアドレスを自動更新
```

**NCLK は立ち下がりエッジでサンプルされる**ため、PIO のサイドセットでデータ出力と同時に NCLK を制御する設計が最適。

### 5. ソフトウェアアーキテクチャ

```
┌─────────────────────────────────────┐
│  アプリケーション (Core 0)           │
│  - 描画コマンド                      │
│  - フレームバッファ操作              │
│  - Wi-Fi/BT 通信 (Core 1 or 割込み) │
└──────────┬──────────────────────────┘
           │ フレームバッファ (SRAM)
           ▼
┌─────────────────────────────────────┐
│  DMA コントローラ                    │
│  - フレームバッファ → PIO FIFO      │
│  - チェーンDMA でスキャンライン連続  │
│  - CPU 介入なし                      │
└──────────┬──────────────────────────┘
           │
           ▼
┌─────────────────────────────────────┐
│  PIO Block 0                        │
│  SM0: HSYNC/VSYNC タイミング生成    │
│  SM1: RGB + NCLK 出力               │
└──────────┬──────────────────────────┘
           │ 20 GPIO
           ▼
┌─────────────────────────────────────┐
│  LTA042B010F (400×96 TFT LCD)      │
│  CCFL バックライト(インバーター経由) │
└─────────────────────────────────────┘
```

## 電源設計

### 必要な電源レール

| 電源 | 電圧 | 用途 | 生成方法 |
|------|------|------|---------|
| 3.3V | 3.3V | Pico 2W + LCD ロジック | Pico 2W 内蔵レギュレータ |
| 5V | 5V | LCD GVDD (推奨) | USB VBUS or 外部供給 |
| +12V | +12V | LCD VGON + CCFL | DC-DC昇圧 or 外部 |
| −12V | −12V | LCD VSS | DC-DC反転 or チャージポンプ |
| DC 12V | 12V | CCFLインバーター入力 | +12Vと共有 |

### 推奨電源構成

```
USB 5V ──┬── Pico 2W (3.3V内蔵)
         │
         ├── LCD DVDD/AVDD (3.3V, Pico 3V3_OUT から供給)
         ├── LCD GVDD (5V, VBUS から直接)
         │
         └── DC-DC 昇圧 ── +12V ── LCD VGON
                         └── CCFLインバーター
             DC-DC 反転 ── -12V ── LCD VSS

※ DC-DCノイズ対策としてLCコモンモードフィルタ推奨
```

## リスクと課題

### 中リスク

1. **±12V 電源設計**
   - DC-DC コンバーター + ノイズ対策が必要
   - 対策: MAX660(チャージポンプ)、ICL7660(反転)、MC34063A(昇圧) 等

2. **CCFL バックライト**
   - 高電圧（数百V AC）で危険
   - 対策: 秋月のインバーターセットを使用し、絶縁対策を徹底

3. **NCLK 停止禁止**
   - PIO 停止時にクロックが止まるとパネル損傷の可能性
   - 対策: PIO 初期化を電源投入直後に行い、常時クロック供給

### 低リスク

4. **FPC コネクタ接続**
   - 0.5mm ピッチは手はんだ困難
   - 対策: 秋月 FPC DIP化基板 (110187) を使用

5. **GPIO ピン競合**
   - 20本使用後も6本以上空き
   - 対策: ピン割り当てを事前計画

## 開発言語の選択

| 言語 | 利点 | 欠点 | PIO対応 |
|------|------|------|---------|
| **Rust (rp-hal)** | メモリ安全性、モダン | エコシステム発展途上 | pio-rs マクロ対応 |
| C/C++ (pico-sdk) | 公式ライブラリ、scanvideo_dpi | 安全性 | PIO アセンブラ対応 |
| MicroPython | 開発速度 | 性能不足の可能性 | 基本的なPIO対応 |

**推奨: Rust (rp-hal)** — ワークスペースが Rust プロジェクトであり、pio-rs で PIO アセンブリを Rust マクロとして記述可能。

## 先行事例との比較

| 事例 | MCU | クロック | 色深度 | fps | 難易度 |
|------|-----|---------|--------|-----|--------|
| STM32F103 (mikanplus) | 72MHz | 15bit | 30Hz | 中 |
| ESP32-S3 (pol) | 240MHz | 16bit | 60Hz | 低（LCD_CAM） |
| AVR XMega (Kyotani) | 32MHz | - | 30Hz? | 高 |
| **Pico 2W (本プロジェクト)** | **150MHz** | **18bit** | **60Hz** | **中（PIO活用）** |

Pico 2W は ESP32-S3 に次ぐ高性能で、PIO による専用ハードウェア制御により、ESP32-S3 の LCD_CAM ペリフェラルに匹敵する効率的な実装が可能。

## 結論

LTA042B010F を Pico 2W の PIO で駆動することは **十分に実現可能** であり、技術的障壁は低い。

- ピンアサイン・タイミングはコミュニティ解析で**完全に解明済み**
- 3.3V ロジックでの動作が**確認済み**
- 400×96 の低解像度は RP2350 のリソースに対して**余裕あり**
- PIO + DMA により **CPU 負荷ゼロ**のリアルタイム表示が可能
- 主な課題は **±12V 電源設計** と **CCFL バックライト** のみ

多数の先行事例が存在し、特に ESP32-S3 での実装 (pol氏) が Pico 2W での実装の参考になる。
