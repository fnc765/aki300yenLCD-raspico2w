## 失敗モードと対策

| 症状 | 原因候補 | 対策 |
|---|---|---|
| PDFの原点付近にReference/Valueが二重に出る | 埋め込みライブラリのデフォルトフィールドを表示している、またはインスタンスパスが`/`のまま | ライブラリ定義のデフォルトReference/Valueを隠し、インスタンス側の表示フィールドを一つにする。プロジェクトのシートUUIDに対応した`(path ...)`を使う |
| 回路図上では隠したラベルがPDFに出る | KiCadのネイティブプロッタがhidden local labelを扱う版差、極端なズーム、隠し属性の位置 | `hide yes`を付け、PDFで実際に確認する。必要な電気接続はまず配線で解決し、最後の互換性フォールバックだけ極小フォントの補助ラベルにする |
| 見た目は接触しているのにERCでpin_not_connected | ピン端点と配線端点がグリッド上で一致していない、回転後の座標を取り違えた | 標準ライブラリのピン端点を計算し、配線端点を同一座標に置く。ERCを必ず再実行する |
| 接続点を減らしたらネットが分断された | 直線上の点とT字/ピン端点を区別せず削除した | 配線内部点数・配線端点数・ピン端点を数え、T字、十字接続、ピン、端子アンカーを残す。ネットリストの`(nets ...)`を比較する |
| A4化後に回路がタイトルブロックへ重なる | ページ変更だけして回路本体を再配置していない、または移動量が不足 | ページ枠とタイトルブロックを含む純正PDFを確認し、回路本体のバウンディングボックスをページ中央寄りへ移動する。LCDなど背の高い記号の下端も確認する |
| 再生成するたび回路がずれる | 生成済み出力を入力にして、シートオフセットを二重適用している | 不変のベース入力を使うか、A4/レビュー済み状態を検出して一度だけ論理座標からシート座標へ変換する |
| A4化済みの再生成でPicoのラベル/no_connectが消える | 元オブジェクトの抽出条件が旧座標だけを見ている | 既に移動済みの`label`/`no_connect`をオフセット分戻して判定し、最終変換時に一度だけ移動する。再生成後のERC急増を検知する |
| 電源レールの文字が読めない | `+5V`と`PWR_FLAG`、または`GND`と補助ラベルが同じ位置にある | 電源フラグのシンボルは残し、冗長なValue文字列だけ隠す。主ネット名を一つの読みやすい位置に置く |
| 部品の値が部品の上や配線上に出る | 回転前のローカルフィールド座標をそのまま使っている、自動配置任せ | 部品ごとにReference/Valueの絶対座標を明示し、配線から離して水平配置する。回転記号ではローカル回転と表示回転を分ける |
| ERCは0だが電源回路が危険 | ERCは定格、極性、インダクタ飽和、電圧リップルを検査しない | データシートと実機条件を別途確認する。特にMC34063の電流検出抵抗、ダイオード、電解コンデンサ、インダクタを再確認する |
| 「KiCad画像」と言いながら枠やタイトルがない | PDFを加工・トリミングしている、または手描き画像を渡している | `sch export pdf`の1ページ全体を保持し、そのPDFをPNG化して確認画像にする |

## S式編集の安全策

`.kicad_sch`はテキストでも、単純な設定ファイルではない。次を守る。

1. `find_balanced`相当の括弧解析でトップレベルブロック、シンボル、プロパティを分離する。改行や文字列内の括弧を正規表現だけで処理しない。
2. UUIDはシンボル、配線、ラベル、接続点、ピンインスタンスごとに一意にする。既存UUIDを意図なく複製しない。
3. 最初の`(at ...)`が必ずシンボルのルート座標とは限らない。シンボル本体、Reference/Value、Footprint、Datasheet、ピンのローカル座標を区別する。
4. シンボルを位置`(x,y)`、回転`r`へ配置するときは、ローカルフィールド座標`(lx,ly)`を次で絶対化する。

   ```text
   x_abs = x + lx*cos(r) - ly*sin(r)
   y_abs = y + lx*sin(r) + ly*cos(r)
   ```

   ただし、すでにシート絶対座標になっているフィールドを二度絶対化しない。入力状態を検出する。
5. `(at ...)`/`(xy ...)`の一括移動では、ローカル座標0付近のインスタンスメタデータを除外する。回路本体だけを移動する。
6. 新しい標準シンボルは、インストール済みKiCadライブラリから抽出して資格付きIDで埋め込む。プロジェクト内のローカル定義と標準定義の名前衝突を避ける。
7. `power_in`、`power_out`、`open_collector`などの電気タイプを、ERCを黙らせる目的だけで変更しない。実部品の動作に合うか確認し、意図的変更ならレポートに記録する。

## 回路図の見た目を崩さない配置

### 配線の優先順位

1. 主要な電源経路とGNDを実線で描く。
2. 分岐を短い直角配線で示し、配線の途中に部品名を置かない。
3. 信号数が多いPico/LCD間は、同名ラベルをピン端点へ置く。ラベル名は`LCD_R0`、`LCD_G0`など一貫した規則にする。
4. ラベルの文字方向と接続点を確認する。ラベルを部品の値の代わりにしない。

### フィールド配置

- 上側の水平レールに部品を置く場合、ReferenceとValueをレールの上側、互いに縦方向へ離して置く。
- 縦置き抵抗・コンデンサ・LEDは、文字を回転させず、部品の左右または上下に水平配置する。
- 部品の値が長い場合は、隣接部品のフィールド幅を見積もって間隔を取る。`1N5819`、`10u 25V`、`GREEN LED`などを重ねない。
- J2、MC34063、C6/C7、RV1のような密集部は、最初から個別のフィールド座標を定義する。最後に自動配置で直す前提にしない。
- Power symbolのReferenceは通常隠す。Valueはネット名として有用なら残し、PWR_FLAGのように冗長なら隠す。

## 接続点整理の判定

配線セグメント`(x1,y1)-(x2,y2)`ごとに、候補座標で次を数える。

- `endpoints`: セグメントの端点と一致する本数
- `interiors`: セグメントの内部にある本数
- `pin_endpoint`: シンボルピンの電気端点と一致するか

判定の目安は次の通り。

```text
keep if interiors >= 1 and (endpoints >= 1 or interiors >= 2)
keep if endpoints == 1 and interiors == 0 and the point is an intentional terminal anchor
remove duplicate coordinates
remove a straight-line point that adds no branch or pin/terminal meaning
```

部品ピンへワイヤが直接終端する場合は`pin_endpoint`だけを理由に保持しない。ワイヤ端点とピン端点を正確に一致させ、ピン上のジャンクションは削除する。ピンへ接続する枝分かれは、ピンから少し離れたワイヤ同士のT字で作り、接続点を端子上から外す。ピン接続に点を足したくなった場合は、まず回転後のピン座標、1.27 mmグリッド、ワイヤの端点を確認する。

候補数だけでなく、保持したワイヤ同士の分岐座標、ピン上の点が0件であること、削除理由をレポートする。接続点を消した後は、配線本数、重複・部分重複ワイヤ、ネット定義数、ピン接続、ERCを再確認する。

## 部品を横切らない配線と電源ブロック

回路図はネットリストだけでなく、読み手が電流経路を追える図面でもある。特に電源ブロックは次の順に配置する。

1. 正電源入力、スイッチング電流経路、ダイオード、出力コンデンサを上側の主経路として置く。
2. 制御ICの制御ピン、検出抵抗、フィードバックを中央に置き、ピンから外へ短い直交配線で引き出す。
3. GNDの戻り線とGNDレールを下側にまとめる。RV1などブロックの下にある部品は、上側の+3V3線を縦に貫かないよう、下側のGND記号・ラベルへ別経路で落とす。
4. 部品本体、ダイオードの記号、電解コンデンサの極性記号、ICの矩形、Reference/Valueを配線で横切らない。必要なら上・左・右・下に配線コリドーを設ける。
5. 同一直線上の部分重複は、端子間の連続した一つのワイヤへ分割して置き換える。単に重複線を消すとピンが未接続になる場合があるため、端子から端子までの経路を再構成する。

コネクタの入力部は、ピン1を上側の+5V、ピン2を下側のGNDへ配置する。コネクタ本体を横切る配線、入力線を上へ折り返して同じネットへ戻す配線、未接続の短い枝を残さない。J2周辺のように部品が密集する場合は、部品の移動とフィールド位置変更を先に行い、最後に配線を引き直す。

## 目視と電気検証の反復

次のチェックリストを1サイクルとして、目視上の問題とERC/netlistの問題を別々に記録する。

- 純正PDFのページ枠・タイトルブロックを含む全体画像を確認する。
- 電源入力、MC34063周辺、チャージポンプ、GNDレールを拡大する。
- ピン端子上のジャンクションが0件か確認する。GNDレール上のT字分岐など、ワイヤ同士の分岐点だけは残ってよい。
- ワイヤと部品の矩形・記号・文字の交差、完全重複、部分重複、dangling endpointを確認する。
- `sch erc`が0エラー・0警告であることを確認する。
- 変更前後のネットリストの`(nets ...)`について、ネット名、ネット数、各ネットのReference/ピン集合を比較する。
- 目視修正後に同じPDFをもう一度出力し、前サイクルの指摘が解消したことを確認する。

ERCが通っていても、ピン上の点、部品を横切る線、値文字の重なり、上下方向のないGND配置は視覚品質の問題として修正対象にする。逆に画像がきれいでも、ネットリストが変わった場合は電気的変更か座標バグを切り分けるまで完了にしない。

## 検査と差分比較

### ERC

```powershell
& $KiCadCli sch erc --severity-all --format report `
  --output "$Out\erc.txt" "$Sch"
```

レポートの最後の「エラー」「警告」の数を読む。CLIの標準出力だけでなく、保存されたレポートも確認する。`lib_symbol_mismatch`を除外して0にする場合は、除外理由と実部品のデータシート確認事項を残す。

### ネットリスト

```powershell
& $KiCadCli sch export netlist --output "$Out\before.net" "$BeforeSch"
& $KiCadCli sch export netlist --output "$Out\after.net" "$AfterSch"
```

比較対象は次の順に狭める。

1. `(nets`からファイル末尾までを抽出する。
2. ネット定義数とネット名を比較する。
3. 各ネットのピン番号とReferenceを比較する。
4. 視覚整理だけなら、同一であることを期待する。差があれば変更を止め、意図した電気変更か座標/抽出バグかを切り分ける。

### 純正PDFと画像

```powershell
& $KiCadCli sch export pdf --output "$Out\schematic.pdf" "$Sch"
```

PDFはページ数を調べ、PyMuPDF等でラスタライズする。PNGを確認用に保存してよいが、成果物の根拠はPDFと`.kicad_sch`にする。ページ枠、タイトルブロック、シート名、ファイル名が残っていることを確認する。

### PCB DRC

```powershell
& $KiCadCli pcb drc --output "$Out\drc.txt" "$Pcb"
```

アートワーク前は未配線エラーが残る。未配線と、シルク重なり、コートヤード重なり、基板端クリアランス、ライブラリ照合警告を分け、未配線だけを理由に全体を不合格にしない。一方で、配置・外形由来の問題を「未配線」と一緒に隠さない。

## PCB移行前の確認

- `Update PCB from Schematic`後に、回路図のReferenceとPCBのReferenceが一対一で対応することを確認する。
- FFCはケーブル挿入方向と接触面を基板外形図で確認する。Picoはアンテナ側、USB側、手はんだパッド周辺のクリアランスを確認する。
- 電源部品は発熱・電流ループ・コンデンサの戻り電流を優先して配置する。単に回路図の左右順をそのまま基板へ写さない。
- 基板外形、取り付け穴、コネクタの張り出し、部品高さ、プローブ位置をアートワーク開始前に固定する。
