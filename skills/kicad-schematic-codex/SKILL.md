# KiCad回路図・基板設計スキル

KiCadを単なる画像作成ツールとして扱わず、電気的接続・シンボル・フットプリント・ネイティブ出力を一体で管理する。回路図の視覚的な美しさだけでなく、KiCadが再度読み込み、ERCを通し、PCBへ正しく反映できることを完了条件にする。

## 作業開始時の判断

依頼を次のどれかに分類して、必要な検査まで進める。

| 依頼 | 最低限の流れ |
|---|---|
| 回路図を読む・レビューする | プロジェクト構成確認 → KiCad純正PDF/PNG出力 → 全体と密集部を目視 → 問題を列挙 |
| 回路図を新規作成・編集する | 部品調査 → シンボル/フットプリント確認 → 配線 → フィールド整理 → ERC → ネットリスト → PDF/画像 |
| PCBへ進める | 上記を完了 → Update PCB from Schematic → フットプリント/外形/クリアランス/アンテナ確認 → DRC → 配置・アートワーク |
| 自動生成・再生成する | 不変の入力を確保 → 生成 → CLI検証 → 純正PDF確認 → 出力をワークスペースへ反映 |

## 標準ワークフロー

### 1. まず現物とリポジトリを把握する

1. `rg --files` で `.kicad_pro`、`.kicad_sch`、`.kicad_pcb`、`sym-lib-table`、`fp-lib-table`、生成スクリプト、README、添付資料を探す。
2. 既存の回路図・PCB・ファームウェア・写真・参考動画の関係を確認する。ユーザーが「電源回路を参考」と指定した場合、Picoのピン配置を勝手に変更せず、指定範囲を守る。
3. 最初に `git status --short` と既存ファイルの差分を確認する。ユーザーの未コミット変更、添付ファイル、中間生成物を成果物へ混ぜない。
4. KiCadの実バージョンとCLIの場所を確認する。Windowsでは例として次を使うが、インストール先を固定値と決めつけない。

   ```powershell
   $KiCadCli = (Get-ChildItem 'C:\Program Files\KiCad\*\bin\kicad-cli.exe' |
     Sort-Object FullName -Descending | Select-Object -First 1).FullName
   & $KiCadCli --version
   ```

5. 変更前の回路図からERC、ネットリスト、可能なら純正PDFを保存する。視覚整理だけなら、変更前後のネットリストの`(nets ...)`部分が一致することを目標にする。

### 2. 部品とフットプリントを実物ベースで選ぶ

- 記号を汎用の四角形や自作の仮記号で済ませず、KiCad標準ライブラリまたは検証済みのローカル記号を使う。
- シンボルのピン番号・電気タイプ・極性・向きをデータシートと照合する。値の文字列が正しいだけでは部品選定完了としない。
- シンボルとフットプリントを別々に選ばず、ピン番号、パッド番号、ピン1方向、接触面、実装高さ、手はんだ可否を一組で確認する。
- Raspberry Pi Pico系はモデルを混同しない。Pico、Pico W、Pico 2、Pico 2 Wの資料と採用フットプリントを照合し、アンテナ側の基板端クリアランスも確認する。手はんだ用途なら、KiCad公式の`Module:RaspberryPi_Pico_W_SMD_HandSolder`のように、実装方式まで明示された候補を優先する。
- FFC/FPCコネクタは型番、36ピン、ピッチ、水平/垂直、接触面、ピン1方向を現物写真と照合する。TE等の候補フットプリントを採用しても、ケーブルの接触面とピン1が未確認なら「暫定」と明記する。
- 電源部品は、ダイオード極性、電解コンデンサ極性、インダクタの飽和電流、抵抗の許容電力、コネクタの電圧定格を確認する。ERCが通っても電源設計が安全とは限らない。

### 3. 回路図を作成・編集する

- 可能ならKiCad GUIで編集し、スクリプト編集が必要な場合は既存の有効な`.kicad_sch`を入力にして、S式を構造単位で扱う。括弧の深さ、UUID、ネストした`(at ...)`を正規表現だけで全置換しない。
- 座標は原則1.27 mmグリッドへ丸める。ピン端点、配線端点、ラベル端点を同じ座標に置き、見た目だけ接触している配線を作らない。
- 部品間の電源・電流経路は実線配線を基本にする。PicoとLCDのような多本数のRGB/同期信号、外部インターフェース、意図的なバスだけを同名ネットラベルで整理する。
- ラベルだけで電源回路全体を描かない。読み手が電流の流れ、GND、分岐、ダイオード極性、コンデンサの充放電経路を追えるよう、主要な電源回路は配線する。
- 内部接続補助ラベルは最後の互換性フォールバックにする。使う場合は`hide yes`だけを信頼せず、KiCad純正PDFで文字が出ないことを確認する。必要なら極小フォントを使うが、通常の回路図で読めるラベルを代用しない。
- 標準ライブラリ記号を埋め込む場合、ライブラリ定義のデフォルト`Reference`/`Value`が原点に二重表示されないよう隠す。インスタンス側には実際に表示するフィールドを一つだけ持たせる。
- シンボルインスタンスのプロジェクトパスは、回路図のシートUUIDに対応するパスを使う。`(path "/")`をそのまま流用すると、ネイティブ出力でデフォルトフィールドが原点に重複描画されることがある。
- シンボルを回転したら、Reference/Valueを自動配置のまま放置しない。水平で、配線・ピン・他の値から離れた位置に明示配置する。回転記号のローカル座標とシート絶対座標を混同しない。
- `PWR_FLAG`など電源シンボルは電気的に残す。文字列がネット名と重なる場合は、シンボルのValue表示だけを隠し、`+5V`、`GND`、`+13V8`などの主ネット名を残す。

### 4. 接続点を整理する

接続点を一括削除しない。各候補について配線端点数、配線内部点数、シンボルピン端点を調べ、次のルールで整理する。

- T字分岐、十字の実接続、シンボルピン端点、外部端子の終端アンカーは残す。
- 同じ座標の重複接続点、直線上で意味を増やさない中間点、単なる配線端点に重ねた冗長点は削除する。
- 十字に見える交差でも、接続点がなければ非接続交差として扱う。見た目だけで接続したことにしない。
- 整理前後でネットリスト、ピン接続、ERCを比較する。接続点の数が減ったことを成功条件にせず、電気的意味が変わっていないことを成功条件にする。
- レポートには候補数、保持数、削除数、4方向接続の座標、採用ルールを残す。

### 5. ページと視覚品質を確認する

- 必ずKiCad純正`sch export pdf`を出し、PDFそのものを確認する。手作業でトリミングした画像、白背景を加工した画像、キャンバスを描き直した画像を「KiCad出力」として渡さない。
- ページ枠、ゾーン記号、ファイル名、タイトル、改訂、サイズ、日付などのタイトルブロックを残す。A3からA4へ変更する場合は、回路本体をページ中央寄りに配置し、タイトルブロックや枠へ重ねない。
- 全体画像で余白とバランスを確認した後、部品密集部を拡大確認する。部品名・値が配線、ピン番号、別部品の文字、タイトルブロックに重なっていないかを見る。
- 次を目視チェックする。
  - Reference/Valueが水平で読める
  - 抵抗、インダクタ、ダイオード、LED、コンデンサの極性・向きが追える
  - 電源レールに明らかな dangling wire がない
  - `+5V`/`GND`/正負電源の名前が重なっていない
  - Pico/LCDの多本数信号ラベルが意図したピンへ対応している
  - 標準回路記号が見え、値の文字だけで部品を推測させていない

### 6. CLIで検証する

候補ファイルを一時ディレクトリへ生成してから、次を実行する。バージョンが異なる場合は各コマンドの`--help`を確認する。

```powershell
& $KiCadCli sch erc --severity-all --format report `
  --output "$Out\erc.txt" "$Sch"
& $KiCadCli sch export netlist --output "$Out\after.net" "$Sch"
& $KiCadCli sch export pdf --output "$Out\schematic.pdf" "$Sch"
& $KiCadCli pcb drc --output "$Out\drc.txt" "$Pcb"
```

- ERCはエラー0・警告0を基本とする。意図的な記号差分や電気タイプ変更を無視する場合は、理由、対象ピン、実部品の再確認事項をREADMEと検査レポートに残す。
- ネットリスト全体はUUIDや生成日時で変わることがあるため、視覚整理の比較では`(nets ...)`部分を比較する。ネット定義数、ネット名、ピン対応が同一であることを確認する。
- PDFは1ページであることを確認し、PyMuPDF等でPNGへラスタライズして`view_image`で確認する。画像の解像度やファイルサイズだけで合格にしない。
- Windowsの`kicad-cli`でHKCUレジストリへのアクセス警告が出ても、プロセス終了コード、出力ファイル、ERC結果を別々に確認する。警告文字列だけで失敗と判断しない。

### 7. 再生成と座標変換を安全にする

- 入力ソースと生成先を分ける。生成済みのA4回路図を次の入力にして、同じシートオフセットをもう一度適用しない。
- 生成スクリプトを再実行可能にする。A4化済みか、レビュー済みマーカーがあるかを検出し、ラベル・`no_connect`・シートオブジェクトの座標を論理座標へ戻してから一度だけ変換する。最初から不変のベース入力を指定する方が安全なら、その方式を選ぶ。
- `(at ...)`と`(xy ...)`を移動するとき、シンボルのローカルフィールド、インスタンスメタデータ、シートUUIDのパスを一緒に移動しない。根本オブジェクトだけを変換する。
- 変更後にPicoのラベルや`no_connect`が欠落していないかをERCで確認する。再生成でERC違反が急増したら、配線より先に座標二重変換と元オブジェクトの抽出条件を疑う。

### 8. PCBへ移行する

回路図が検証済みになってからPCB Editorで`Update PCB from Schematic (F8)`を実行する。

- すべてのフットプリント、パッド番号、部品リファレンス、ピン1方向を確認する。
- 基板外形、Picoアンテナ周辺、FFCの挿抜方向、電源コネクタ、手はんだスペース、コンデンサ極性を配置前に確定する。
- 未配線数と、未配線以外のシルク・コートヤード・基板端クリアランス・ライブラリ照合警告を分けて記録する。
- アートワーク前は、銅箔配線を始めることではなく、部品配置と制約が正しいことを確認する段階と扱う。最終配線後に改めてDRCを実行する。

## 手渡しの形式

完了時は、次を短く報告する。

1. 変更した内容と、画像で見つけた問題をどう直したか。
2. ERC結果、ネットリスト比較、PDFページ数、PCB DRCの解釈。
3. KiCadが生成した`.kicad_sch`と純正PDF/PNGへの絶対パスリンク。
4. 部品型番、FFC接触面、Picoモデルなど未確認事項。
5. コミット済みか、今回の差分が未コミットか。

確認画像を提示するときは、KiCad純正PDFを元にしたPNGを使う。接続補助ラベル、意図的なERC例外、暫定フットプリントを隠して完成品のように見せない。

詳細な失敗例、S式編集の注意、検査コマンドの解釈は[references/kicad-knowhow.md](references/kicad-knowhow.md)を必要な箇所だけ読む。
